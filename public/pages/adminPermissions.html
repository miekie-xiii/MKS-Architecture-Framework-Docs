Admin Permissions

The MKS Architecture Framework uses a hierarchical permission system to control which players an administrators can manage. Permission checks are based on both the role of the actor and the role or status of the target.

Permission Hierarchy

Higher-level administrative roles can manage lower-level players, while protected players cannot be targeted by players with equal or lower permission levels.

Role Permissions

Admin and Temporary Admin

Admin and Temporary Admin players can perform administrative actions against Normal Players. They cannot target other administrative players, Temporary Root players, Protected Players, or Root players.

Temporary Root

Temporary Root players have a higher permission level than Admin and Temporary Admin players. They can target Normal Players and Admin or Temporary Admin players, but cannot target other Temporary Root players, Protected Players, or Root players.

Root

Root players have the highest administrative authority in the permission hierarchy. They can target Normal Players, Admin players, Temporary Admin players, Temporary Root players, and Protected Players. However, Root players cannot target other Root players.

This prevents Root-level players from modifying or removing players with the same highest-level authority.

Protected Players

Protected Players are Normal Players with immunity against administrative actions. They cannot be targeted by Admin, Temporary Admin, or Temporary Root players. Only Root players can perform administrative actions against a Protected Player.

Permission Check

Before an administrative action is performed, the system validates the actor's permission level against the target's role or protection status. If the actor does not have the required permission, the action is denied.
