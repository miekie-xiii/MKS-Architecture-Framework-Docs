Introduction

The MKS Architecture Framework was created from Miekie's experience with Krunker map development. While building maps, Miekie encountered the 500,000-character game data limit, partly because administrative scripts could become large and consume a significant amount of the available space.

To address this problem, Miekie developed an administrative system designed to remain lightweight while keeping important validation and control on the server. This approach eventually developed into the MKS Architecture Framework.

Built from Map-Making Experience

The framework is built around practical experience gained from creating and managing Krunker maps. Its design focuses on providing the general systems that a map maker may need without unnecessarily adding features that increase script size or complexity.

The MKS Architecture Framework may not include every feature that every map maker wants or requires. Instead, it provides a foundation of commonly needed functionality, including server administration, permissions, logging, and server-client communication.

Lightweight by Design

Because Krunker maps have a 500,000-character game data limit, keeping systems lightweight is an important part of the framework's design. The MKS Architecture Framework aims to reduce unnecessary complexity while keeping its systems modular and easier to manage.

The goal is not to provide every possible feature in a single framework, but to provide a practical and extensible foundation that covers the general features needed for map administration and server management.
